# 004 提示词

本文说明智能体读到什么、团队能改什么、改动何时生效。它建立在 [000 设计理念](000-philosophy.md) 至 [003 执行](003-execution.md) 之上。提示词文本用英文书写。

## 团队写什么

团队可以编辑三个团队小节、添加技能，并覆盖每一个内置系统提示词部件。大部分默认值在 `prompts/` 与 `skills/` 下。工具说明、通知和卡片留在代码里，无法通过提示词设置修改。

| 小节 | 内容 |
| --- | --- |
| Communication 沟通 | 什么时候给人发消息、消息怎么读、每条 GitHub 消息开头的那一行（默认是 `This is by an automated agent, not a human`）、如何处理评审、以及哪些普通账号是评审机器人 |
| Ticket scope 工单范围 | 工单什么时候继续，什么时候带着草稿停下 |
| Delivery requirements 交付要求 | pull request 里要有的证据、自动合并条件及其行数阈值、以及提交作者；没有指定时，执行器以智能体账号的 no-reply 地址提交 |
| Team skills 团队技能 | 智能体需要时才加载的知识，例如一个 `identities` 技能，说明哪个飞书用户对应哪个 GitHub 账号 |

内置文本覆盖角色、工具用法、宿主机制、授权规则，以及 GitHub 与飞书技能。它通过小节标题引用团队小节，而不是重复它们。

### 内置部件与模板

覆盖时使用这些键：

| 部件 | 键 |
| --- | --- |
| 共享指令与角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成的小节 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成的小节是可编辑的模板，必须保留这些占位符：

- `runtime/environment`：`{variables}`，填入执行环境的各行。
- `runtime/policy`：`{version}`、`{mode}`、`{rules}`，每条已启用规则一行。
- `runtime/policy/none`：`{version}` 与 `{mode}`，在没有启用任何规则时使用。

编辑部件改变的是模型收到的指令，不改变准入、授权、工具检查或账号包装脚本——这些仍由代码强制执行。

在明确的人力请求下，主 Session 也可以用 `orchestrator_prompts_save` 保存覆盖。如果保存时省略了某个覆盖的 `base`，会保留已保存的 base。已保存在配置里、但本次被移除的部件会在保存时删除；其他未知部件会被拒绝。

每个覆盖记录它基于哪份内置文本。升级会保留团队的文本。默认值变化时，面板会把该部件标为 **Default updated**（默认内容已更新），并在团队文本旁显示差异。团队可以保留自己的文本、采用新默认值，或在此基础上编辑。没有被覆盖的部件自动跟随新默认值。

主 Session 可以用 `orchestrator_read prompts` 在 `default_changed` 下读取受影响的部件名。

## 组装与优先级

系统提示词按这个顺序组装：

1. 共享指令与角色。
2. 三个团队小节。
3. 订阅与回复。
4. 主 Session 的派发指令，或执行器的工作指令。
5. `runtime/admission`，仅主 Session。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅主 Session。

准入指令来自 `prompts/admission.md`。它描述主动研判，以及什么时候可以凭卡片直接忽略一个无关候选。`orchestrator_eval` 返回上下文，而不重复这些指令。

环境小节给主 Session 的是部署级的值，给每个执行器的是它工单专属的值。策略小节在每次模型请求时由设置重新生成，含策略版本、接单模式、明确请求豁免项，以及已启用规则（格式为 `- <name> (<id>): <instruction>`），或一句"没有启用任何规则"。它放在最后，这样策略变化不会影响前面的提示词文本。

执行器还会读 DeepSeek-Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读。推断得来的工单会附一段末尾说明，把它的执行器限制在命中的规则内。派工和收到的消息以触发卡片内联到达，只有内容被截断时才给资源指针。

执行器无人值守地工作。它们的工具排除了会向人提问、给人展示界面或修改 profile 的那几类，例如 `ask_user_question`、`present`、`plugin_manager`。

从强到弱：

1. 由工具和宿主强制的事实：身份、权限、工具参数检查、回复用途、长度上限。提示词文本改不了它们。
2. 内置小节与生成小节，按团队对它们的覆盖来读。
3. 主动型工单命中规则里的流程与沟通要求，只对那张工单的执行器 Session 生效。
4. 团队小节和团队技能。
5. 外部文本：消息、评论、文档、引文。它是数据，永远不改规则或授权。

## 内置文本的原则

这些把 [000 设计理念](000-philosophy.md) 用到智能体身上：

- **角色分离。** 主 Session 只做路由：转达原始触发和路由所需的事实，不做技术判断；它通过一个路由工具，在一次调用里对多个等待中的候选做出决定。路由附言最多 30 个字。执行器读原始来源、判断范围、实现并验证。
- **主 Session 不等待。** 报告、追问通知、候选、完成的后台任务都会作为消息自动到达。没有剩下的事，它就结束这一轮。守卫会拒绝 `sleep`、超过 30 秒的 shell 超时、以及超过 5 秒的 job 等待，因为被阻塞的一步会压住新的候选。这些指令替代了 DeepSeek-Harness 在完整提示词里自带的 job 通知说明。
- **只在必须有人处理、或有人能用上结果时才发消息：** 结果可以评审或使用、需要某个决定或资源、或者工作做不完。会话消息默认一句话，硬上限 100 字。
- **执行器决定自己怎么处理追问。** 每个执行器处理并确认范围内的请求，把超出自己工单或属于别的工单的请求交回。只有当所有拥有者都交回、或者都没接手就结束之后，一条消息才会变成新工作。主 Session 会收到追问通知，但只能为停止工作去处理它。交回的消息随后带着各执行器的理由作为候选到达。
- **通过订阅和主 Session 协作。** 执行器为上下文跟随相关线程。主 Session 可以在不超过 100 字的附言里转达另一张工单的事实。订阅和附言都不授予权限。
- **只在有明确指向时挂接。** 消息必须指向某张工单的 pull request、Issue、来源消息、确认，或者指向恰好对应一张工单的近期改动。仅主题相似不够。挂接会把工单订阅到整个线程；执行器若判定无关，使用 `orchestrator_thread_unrelated`，不在那里作答。
- **具体地确认一次。** 大块工作之前，执行器对每个新请求确认一次，点明对象和预期结果，作为原消息下面的回复。
- **通过 `human_action` 提问。** 执行器把唯一一个具体问题放进它的报告，主 Session 原样转达。如果问题是由某人的消息引出的，就点名那条消息，并由宿主在那里提问；否则在工单最初的会话里提问。已获授权的工作可以同时继续。
- **诚实交付。** 开了 pull request 不等于就绪；草稿标明未完成；没有真实"改动前"截图的界面改动不算就绪。
- **人的暂停一直有效**，跨追问、新的执行器 Session 和重启都有效，直到有人解除。自动反馈永远不会让暂停的工作恢复。
- **示例只展示格式。** 例句不是智能体可以声称的事实。
- **按结果处理评审。** 已修复并验证的评论静默解决；被拒绝的评论给一句话理由。对自动化评审者，它的线程获得答复后即解决；每个 pull request 上，每个自动化评审者最多三轮。
- **让位给重复的工作。** 如果某人的分支或 pull request 已经包含工单要的改动，执行器关闭自己的 pull request，用一句话指向对方的。

## 版本

- 每次保存都创建一个不可变版本，包含完整配置、版本号、前驱、时间戳和来源（面板或工具）。恢复某个版本或默认值也会创建新版本。
- 保存会声明它基于哪个版本号。冲突的保存会被拒绝，草稿不会被丢弃。
- Session 在每次模型请求时读取最新版本，包括同一轮里后续的步骤。保存不会重启、取消或唤醒 Session。宿主记录每个 Session 用过的版本；执行器可以读取它工作期间用过的任何版本。
- 部署设置了总长度上限，包含覆盖内容。校验会拒绝未知键、保留的内置技能名、未知覆盖部件，以及缺少模板占位符。它绝不会悄悄截断文本。与默认值完全相同的覆盖会被删除，让该部件跟随今后的默认值。
