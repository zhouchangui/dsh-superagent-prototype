# 005 面板

在 DeepSeek-Harness Web 的侧边栏打开 **Superagent** 来监督智能体。面板优先展示需要人处理的工作，其次是系统健康与历史。本文建立在 [000 设计理念](000-philosophy.md) 至 [004 提示词](004-prompts.md) 之上。

## 三个问题

打开面板就回答三个问题，按此顺序：

1. 现在有需要我处理的事吗？
2. 系统是否健康、是否在做该做的事？
3. 某一件工作的历史是什么，从触发经评估到工单？

## 选项卡

选项卡按工作流排列：**概览**（Overview）、**来源**（Source）、**触发**（Trigger）、**评估**（Eval）、**执行**（Execution）、**设置**（Settings）。在仓库与账号设置成功之前，概览会显示缺什么，并链接到相应的设置。

| 选项卡 | 展示 |
| --- | --- |
| Overview 概览 | 需要处理的工单、系统问题、最近 24 小时的活动计数、执行器负载。每个区块都链接到它的详情页 |
| Source 来源 | 来源状态、设置问题和非零计数。被过滤的触发与丢弃的消息，与概览使用同样的 24 小时窗口 |
| Trigger 触发 | 按"已订阅""评估中""24 小时内新触发""所有线程"筛选的线程。每个线程按时间倒序展示它的触发、决定和订阅 |
| Eval 评估 | 决定及其理由和命中的规则 |
| Execution 执行 | 执行器状态、"暂停处理"，以及按"未结束""待启动""执行中""在等触发""已结束"筛选的工单。工单详情展示操作、授权、等待中的输入、订阅和派工 |
| Settings 设置 | 来源、评估、执行、提示词、部署。每组都含它的保存历史 |

### 阅读单条记录

被丢弃的消息会链接到它的工单；没有工单时链接到它的线程。来源页会说明是该会话消失了，还是来源停止了监听。

仍归执行器拥有的人发来的追问会标记为 **Delivered to Ticket**（已投递到工单），不经过评估。线程上也会显示交回的理由和仅作上下文的订阅。**Evaluate again**（重新评估）可以把这条追问送进评估，也可以重试一个没有有效判断的触发：被来源过滤掉的、评估为 `unavailable` 的、或者已投递但既无"非停止"决定也无执行器确认的消息。

工单详情展示发起它的触发、决定与理由、范围和策略版本。派工与次要细节折叠在即时操作之下。**Retry**（重试）用于输入投递失败，或在 `blocked`／`failed` 报告之后正在等人的工单。已结束的工单显示结果，例如 **Pull request merged**（pull request 已合并）或 **Stopped by a person**（被人停止）。

## 设置分组

- **Sources 来源：** 每个来源一张卡片，含开关、字段和已验证的账号事实。GitHub 还为新 Issue、pull request、评论和默认分支 CI 提供"接收全部"开关。轮询与读取上限在 Advanced 下。
- **Eval 评估：** 策略版本与规则，然后是 **On each Source**（每个来源上）与评估设置。每个来源页含它的允许名单、成员同步、准入表和机器人名单。同步在启动时以及点 **Sync now**（立即同步）时运行。准入表区分接收范围、发送者是否在名单上、以及消息是否在找智能体。评估设置选择接单模式、超时和研判模型。
- **Execution 执行：** 工作节点模型、并发数、目录根、prepare 命令和被禁命令。点击可用变量会把它插入 prepare 命令。
- **Prompts 提示词：** **Edit**（编辑）修改团队小节、内置部件和技能。**Full prompt**（完整提示词）显示组装后的文本，并与已保存文本或默认值对比。**History**（历史）列出各版本。被编辑过的内置部件会标为已更改，并可重置；模板会列出必需的占位符。

  升级导致某个被覆盖的默认值变化时，会把它标为 **Default updated**（默认内容已更新）。面板会在团队文本上方对比新旧默认值。如果没有记录旧默认值，则改为把团队文本与新默认值对比。选择 **Keep my text**（保留我的文本）或 **Use the new default**（采用新默认）。已移除部件的覆盖会列在选项卡栏下方，并在下次保存时删除。
- **Deployment 部署：** 启动问题（带 **Check again** 重新检查）、状态目录和机器上限。保存的上限无需重启即可生效。DeepSeek-Harness 的插件管理器暴露同一页面。

## 搜索

顶部搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL）查找触发。原消息里没有的飞书链接，只有在当前进程生命周期内被宿主读过之后才能被搜到。

搜索也能按 `#12` 或 GitHub URL 这类引用找到线程，并按标题或匹配的线程找到工单。

## 原则

1. **聚焦要紧的事。** 每个元素都要回答三个问题之一，否则删掉。一个数字只有在会改变监督者行为时才出现。
2. **定义精确。** 分类有可检验的定义、互斥，并且覆盖所有情形，就像工单阶段那样。标签要说明这一行在等谁、需要什么，而不是内部状态码。
3. **一个概念只占一处。** 来源状态在来源页；线程与触发在触发页；决定在评估页；工单在执行页。设置按它所配置的概念分组。概览只概括这些页面并链接过去，而不变成又一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识符只出现在折叠的细节里，能解析出名字的地方就用名字代替标识符。
5. **诚实的状态。** 计数等于它所链接列表的长度，任何状态都不与别的事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须是可行动的；一次偶发网络错误不够。需要人处理的行直接提供它的操作。页面说明保持一句话，更多细节放进 (?) 提示里。破坏性操作需要确认。
7. **一致的控件。** 使用 DeepSeek-Harness 的设计 token 和控件行为。同样的信息在整个面板里看起来应该一样。每个设置区块只有一条保存栏，只在有改动、正在保存或保存失败时出现。
