# 000 设计理念

dsh-superagent 是一个框架，也是一种与智能体协作的方式。它的核心原则：

**尽量少占用人的注意力，尽量多地交付价值。**

项目的每个部分都以它消耗的注意力来评判。一条消息、一个通知、一个提问、一项设置、一个面板元素、一段文档，各自都花掉某个人的注意力，所以每一项都必须给出超过这份成本的价值，否则就删掉。

## 对智能体的要求

- **只在被请求时行动，或在成文规则允许时行动。** 一个请求只有在直接对智能体说、并且来自团队允许的人时才算数：要么在允许名单上，要么在团队开放了请求的会话里。没人要求的工作，需要团队写下的规则，并且一开始只用一种只记录"智能体本来会做什么"的模式运行。
- **只在必须有人处理、或有人能用上结果时才开口。** 它在收到请求时确认一次，并说明自己会做什么。干活期间保持安静。出结果时、需要决定时、做不完时，才再写一次。消息要短，回到提出请求的那个会话里。
- **一次只问一个具体问题**，用结构化的形式，让问题直接到达人手里，而不是埋在长篇报告里。
- **按影响停，而不是按投入停。** 本地改动一直做到可评审的结果。需要设计决定的改动，就带着一个清楚的问题停下来。
- **如实报告。** 草稿标明未完成，失败就说失败，绝不为回避提问而绕过限制。

## 对设计的要求

- **概念要少。** 设计里只有它的领域概念（例如来源）和这些概念的具体实现（例如 GitHub 与飞书）。业务需求会变成其中某个概念的属性，或者变成智能体遵循的一段提示词。设计不为它新增概念。
- **设置要少。** 当某个值几乎适合所有团队时，用默认值代替设置。团队用文字描述的行为是提示词文本，不是设置。
- **面板只展示需要人处理的东西。** 先列出在等人的项。健康状态不占任何空间。
- **文档按顺序读。** 每篇编号文档只依赖它前面的文档，读者永远不需要还没介绍过的概念。

## 责任

智能体用团队每天都看得见的账号发表评论、开 pull request、给人发消息。它发出去的每一条消息都花掉同事的注意力，这份责任在你。智能体能做的事越多，操作者对团队就越要用心：

- **从窄处开始。** 先给一个短的允许名单，主动发现的工作只做记录。等"它本来会做什么"看起来对了，再把两者放开放宽。
- **为了更少的噪音去调。** 智能体太吵时，把它的提示词改短、改严，或者暂停它。不要靠加更多消息去解释噪音。
- **不要用它制造数量。** 大批量的 pull request、群发消息和无用忙碌，花掉团队的比给出去的更多。
- **对它说的话负责。** 读懂智能体以你的名义发布的内容，发现错了就在提示词里纠正。

目标是：在对的时候给出对的帮助，其他任何时候什么都不要。
